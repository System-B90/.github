    UX Guidelines¶

    Owner: @yoni254 (UX Engineer). Changes to this file, the theme, or a shared UI primitive need their review (see .github/CODEOWNERS).

    Status: draft, not yet reviewed. Nobody has signed this document off yet, and until @yoni254 does, treat every rule here as a suggestion. Where a rule and good judgment disagree, use judgment and say so in the PR.

    This document describes how Bluz should look, read and behave. Once it is reviewed, a disagreement between code and this document means the code is the bug, unless the PR that changes the code also changes this document.

    The schedule surface (ui/src/components/schedule/) and the settings dialog (ui/src/components/settings-dialog/) are the reference implementations. Gantt and the student view are being brought in line. Their known gaps are listed in §10.

    Quick Start¶

    Before you open a UI PR:

    npm run lint                      # ESLint + style rules
npm run test:unit                 # includes tests/backend/theme-contrast.test.ts
python tools.py dev status        # reuse the running dev server if it's up
python tools.py dev               # else start one, then open https://bluz.dev

    Then go through the review checklist and attach before/after screenshots (light and dark) to the PR.

    1. Principles¶

    1. One way to do a thing. If a pattern exists, use it. If it's wrong, fix it everywhere. Don't fork it.
    2. The schedule is a work tool. Users spend hours in it. Density and speed beat decoration. Animate only to explain a change of state. Never animate to attract attention.
    3. State is visible. Every toggle shows whether it's on. Every async action shows that it's running, then whether it worked.
    4. Reversible beats confirmed. If an action can be undone, don't ask. Do it and say what happened. Ask only when it can't be undone, hits other people's work, or acts on many things at once.
    5. Hebrew-first, RTL-native. Design and write in Hebrew. Never translate an English layout.

    2. Foundations¶

    All values come from the theme (ui/src/components/theme/CreateFromPalette.ts). Never add a hex color, a shadow string or a pixel radius in a component.

    Color¶

    Use Token
    Brand fill (contained buttons, active toggles, badges) primary.main
    Brand as text or icon primaryText.main. color="primary" on Typography, Link, SvgIcon, IconButton and text/outlined Button already maps to it.
    Body / secondary / disabled text text.primary / text.secondary / text.disabled
    Lines and borders divider
    Hover / selected backgrounds action.hover / action.selected
    Status success / info / warning / error, each for its meaning only
    Event colors event-component/event-colors.ts, the only place that turns an event color into a tile color
    • The 4 color schemes (light, dark, pink, pink-dark) are checked for contrast by tests/backend/theme-contrast.test.ts. A new text/background pairing goes in that test.
    • Tints: alpha(theme.palette.X.main, 0.08–0.18), or with CSS vars, rgb(${theme.vars.palette.X.mainChannel} / 0.12).
    • Color is never the only signal. Pair it with an icon, a label or a shape.

    Typography¶

    The font is Assistant. Use MUI variants, not fontSize.

    Role Variant
    Page / calendar range title h6, bold
    Dialog title h5, bold (event dialog) or the default DialogTitle
    Popover / panel heading subtitle1, weight 700
    Body, menu items body2
    Meta, counts, hints, keyboard shortcuts caption / body2 + text.secondary

    The exceptions are the two dense grids: schedule event tiles (event-component/) and the Gantt grid cells (gantt/curriculum-view/tabs/gantt-view-tab/). They are micro-layouts sized in rem. Don't copy their sizes anywhere else.

    Spacing, radius, elevation¶

    • Spacing is theme units only: 0.5, 1, 1.5, 2, 3. Toolbar groups use gap: 1.5. Popover padding is 2. Dialog content uses gap: 3.
    • Radius comes from the theme: Paper (popovers, menus, cards) = 12px (borderRadius: 3), Dialog = 20px. Don't override it on a Dialog, Popover or Menu paper. Chips and small surfaces use borderRadius: 1–2. Inputs and buttons keep the theme's radius. Don't add a per-surface radius (settings used to set 10px on every field).
    • Shadows: theme shadows only (boxShadow: 2 resting, 4 lifted, 8 for a drag overlay). Popovers and menus get their elevation from the theme. Cards inside a dialog have a border and no shadow.

    Motion¶

    • Use theme.transitions.create([...], { duration: theme.transitions.duration.shorter }). Keep durations between 150 and 300ms.
    • Never use transition: "all …". Name the properties.
    • No infinite animations, except a live-presence signal that must be noticed (the "someone is editing" lock badge).
    • prefers-reduced-motion: reduce is honoured app-wide by style/globals.css, which collapses every animation and transition. A component only adds its own media query when reduced motion needs a different end state (e.g. hiding an exit row), not just "no animation".
    • No hover-scale, pulse or bounce on controls. Hover shows a color/background change. Press shows the ripple.

    3. RTL and bidi¶

    • Use logical properties only: marginInlineStart, paddingInlineEnd, insetInlineEnd, borderInlineStart. Never use ml/mr/pl/pr, left/right or marginLeft.
    • Exception: centering with left: 50% + translateX(-50%). Comment it, as CalendarToolbar.tsx does.
    • Popover anchorOrigin.horizontal is physical. Pick the side that opens inward.
    • Wrap Latin and mixed content (names from Hive, keyboard shortcuts, codes like R-50) in <bdi>, or render it with dir="ltr" (MenuShortcut does this).
    • Day names are full words (יום ראשון), never single letters.

    4. Hebrew copy¶

    Voice¶

    Where Form Example
    Buttons, menu items, tooltips, aria-labels Action noun (שם פעולה). Gender-neutral. שמירה · מחיקה · הסתרת סרגל כלים · יציאה ממסך מלא · מעבר למצב לוקלי
    Instructions and hints in body text Plural imperative (addresses everyone) גררו לכאן מופע כדי…
    Confirmation question Infinitive question + consequence למחוק את הטיוטה "X"? לא ניתן לבטל.
    Confirmation button Action noun, the specific verb מחיקה · פתיחה · הסרה. Not "אישור", not "כן".
    Toggle tooltip Says what the click will do הצגת סננים ↔ הסתרת סננים

    Never use the masculine singular imperative (עבור, חזור, צא, בחר). It addresses only half the users, and the rest of the UI doesn't speak that way.

    Status messages¶

    Kind Pattern Example
    Success <object> <past verb>. הטיוטה נשמרה לשרת.
    Failure <action noun> נכשל/ה!. Details come from enqueueApiErrorSnackbar מחיקת הטיוטה נכשלה!
    Count number first, then a plural noun 3 מופעים נמחקו
    Read-only one shared string READ_ONLY_ITERATION_MESSAGE

    Glossary¶

    Use one word per concept, everywhere.

    Concept Term Not
    An item on the calendar מופע / מופעים אירוע (that means a Google Calendar event)
    A run of the program (iteration) מחזור איטרציה
    Group of students in a syllabus שאפל
    Unassigned events box ארגז
    Shared server-side draft טיוטה
    Saved week layout תבנית שבוע
    Restore point צילום מצב גיבוי
    Filters סננים מסננים
    Classroom / room Open decision (@yoni254). The schedule says כיתה (event field, grid column, student view). Settings says חדר (76 strings vs. 20). Until it's decided, use the term the surface already uses.
    Instructors list מבוזרים
    A schedule item, as the Gantt names it Open decision (@yoni254). Gantt calls its own blocks מופע and the schedule items a cut creates אירוע (gantt/glossary.ts). The schedule calls the same items מופע. Gantt copy was left as is.

    5. Components and patterns¶

    5.1 Buttons¶

    • At most one variant="contained" primary action per dialog or popover.
    • Secondary actions are text (in dialogs) or outlined (in toolbars).
    • Destructive actions use color="error". Never make them the default focus.
    • Long actions disable the button and swap its icon for <CircularProgress size={16} />. The button doesn't change size.

    5.2 Icon-only controls¶

    Every icon-only control needs a Tooltip and an aria-label with the same text. Use the shared button for the surface. It does this for you:

    Where Component
    Schedule toolbar and its floating chrome ToolbarIconButton (schedule/calendar/calendar/). Keeps disabled buttons hoverable and renders toggle state.
    App bar HeaderIconButton (header/). Takes href for navigation (renders a link, not a button) and pressed for toggles.

    When an icon button repeats per row, the label names the row: הסרת ${name}, שעה נוספת ב${day}. Many identical "מחיקה" buttons are useless to a screen reader.

    5.3 Toggles¶

    A toggle's "on" state is variant="contained" + aria-pressed. Don't paint a custom background. View pickers (יום / שבוע עבודה / שבוע), the offline switch, the filter button and the store menus ("something of mine is open") all work this way.

    5.4 Toolbars¶

    • Controls are grouped by job into ButtonGroup size="small" variant="outlined" with sx={TOOLBAR_GROUP_SX} (32px tall).
    • Schedule order, from the start (right) edge: navigation (קודם / היום / הבא) · range title · stores (טיוטות, תבניות, צילומי מצב, בדיקה, ייצוא) · view · mode (מקוון/לוקלי, סננים) · chrome (עזרה והדרכה, הסתרת סרגל, מסך מלא).
    • The "?" (עזרה והדרכה) opens the help panel, which lists every schedule tutorial. Along with the palette (type הדרכה) it is the only way into them.
    • A control that can never act in this context is hidden, not disabled. Disabled-with-tooltip is for "not now, and here's why" (read-only מחזור, nothing to export).

    5.5 Menus¶

    • ListItemIcon with a fontSize="small" icon on every item, or on none in that menu.
    • Keyboard hints go in MenuShortcut (end-aligned, dir="ltr", secondary text).
    • Order: clipboard → structure → assignment → navigation → destructive last, after a Divider, in error.main.
    • Write actions in a read-only מחזור stay visible and disabled, so the menu doesn't change shape.

    5.6 Dialogs¶

    • The title names the action and the object: מופע חדש when creating, עריכת מופע when editing.
    • Alerts that change what the user can do (read-only, locked by another user) go first, above the form.
    • DialogActions, in RTL reading order: destructive at the start (marginInlineEnd: "auto") · ביטול · primary (contained) at the end.
    • An action that can't apply (Delete on an unsaved event) isn't rendered at all.
    • A primary action that is disabled says why, in a Tooltip on it (יש להזין שם למופע). A greyed-out שמירה alone leaves the user guessing what to fix.
    • A form dialog with real input (the event dialog) never loses edits silently. Esc, a click outside and ביטול all go through one close handler that confirms when the form is dirty: לסגור בלי לשמור? · חזרה לעריכה / סגירה בלי שמירה. An untouched form closes at once.
    • Settings list + form tabs get the same guard from useEntityForm: picking another row, "add" and ביטול ask when the form is dirty (לבטל את השינויים?). The form reports itself to the settings dialog (useReportUnsavedChanges), so closing the dialog or switching tabs asks too. A save or delete clears the form without asking.
    • Confirmations go through useConfirmDialog. Always pass title and a specific confirmLabel. The defaults are a fallback, not a design.

    5.7 Confirm vs. undo¶

    Action Pattern
    Single event edit/move/delete (undoable via Ctrl+Z) No confirm. Snackbar result. A delete's snackbar carries a ביטול action that undoes exactly that delete (never a later edit).
    Bulk delete of a selection Confirm with count: למחוק 5 מופעים?
    Deleting anything shared or stored on the server (טיוטה, תבנית, צילום מצב, מחזור, צבע, מסלול) Confirm with name + "לא ניתן לבטל."
    Replacing unsynced local work (opening a draft/template while offline) Confirm and name what is lost. Button names the action (פתיחה).
    Discarding unsynced local work (שחזור הכל in the sync dialog) Confirm with the count + "לא ניתן לבטל."
    Editing an event another user holds Confirm (LOCKED_EDIT_*)

    5.8 Feedback¶

    • Snackbars (notistack): success = done, info = a mode changed, warning = refused or partial, error = failed. Errors always go through enqueueApiErrorSnackbar.
    • Loading: first load of a surface = Skeleton in the surface's shape (CalendarSkeleton). Refresh of a list = small centered CircularProgress. Never use a bare Tailwind block. It ignores dark mode.
    • Empty: base/EmptyState. "Nothing here" and "your filters hid everything" are different variants with different fixes.
    • Errors that block a surface: ErrorSurface inside an ErrorBoundary, with a retry.
    • Validation: an error that belongs to one field shows on that field (error + helperText), and the field takes focus. A snackbar says what is wrong but not where. In settings, validate returns { field, message }; the field needs a matching name. Forms set noValidate, so the browser's own bubble (in the browser's language) never fires first. Don't flag an empty field as invalid while the user is still filling the form; the required check runs on save.

    5.9 Popovers¶

    Use plain Popover or Menu, styled by the theme. Set only p, mt, and a width when the content needs one. Heading = subtitle1 bold, mb: 1.

    5.10 Settings cards¶

    • Every card is settingsCardSx: a border, 12px radius, p: 3, no shadow.
    • Every card header is SettingsSectionHeader: icon badge + subtitle1 bold title + caption subtitle + an optional trailing action (a switch, a button). Don't hand-roll this block.
    • A switch in a header needs an accessible name: slotProps={{ input: { "aria-label": <title> } }}. The header text beside it isn't linked to the input.
    • List + edit tabs use useEntityForm + SettingsListCardContent + BaseFormCard. A deletable entity passes confirmDelete: { title, message }, and the message names the entity.
    • Inline form actions (SettingsFormActions): the submit button stretches and comes first, then ביטול, then tab extras. This is the inline-form counterpart of §5.6 dialog actions.
    • The dialog has a labelled title (aria-labelledby) and a close button with a tooltip. Tab navigation is a list of real buttons with aria-current.

    5.11 Auth pages¶

    Login, access-denied and CLI sign-in share auth/AuthCard.tsx: AuthPage (the scrollable page; body itself never scrolls) and AuthCard (theme Paper, elevation={4}, a border). Don't hand-roll another card for a pre-auth page.

    6. Accessibility¶

    • Every focusable element shows the theme focus ring (focusRing). Never set outline: none.
    • Custom interactive Boxes need a role, tabIndex={0}, Space/Enter handling and aria-checked/aria-pressed. EventToggles.tsx shows how.
    • Hit targets: 32px minimum in dense toolbars, 40px everywhere else.
    • Dialogs trap focus and return it to the trigger. The tests are in tests/dialog-keyboard.spec.ts.
    • Text contrast must pass WCAG AA in all 4 schemes.

    Area File Notes

    8. Process¶

    • Owner: @yoni254 reviews PRs that touch docs/ux-guidelines.md or ui/src/components/theme/. Ask them early for any new pattern. Don't add it and document it later.
    • New pattern? Add it here in the same PR, with the component that implements it.
    • Screenshots: before/after for every affected page, modal or component, in light and dark. Update tests/screenshots.spec.ts when a user-facing page changes visibly.

    9. Review checklist¶

    • No hex, shadow strings, pixel radii or fontSize literals outside event-component/
    • Logical CSS properties only. Latin/mixed text wrapped in <bdi>.
    • Icon-only controls have tooltip + aria-label. Toggles have contained + aria-pressed.
    • Copy follows §4: action nouns, glossary terms, no masculine imperatives
    • At most one contained button per dialog/popover. Destructive is red and comes last.
    • Irreversible or shared deletes confirm. Undoable single edits don't.
    • Loading, empty and error states exist and use the shared components
    • No infinite or decorative animation. Reduced motion respected.
    • Works in light, dark, pink and pink-dark

    10. Known deviations¶

    Not fixed yet:

    • Settings: the dense rows of the course builder (CourseItem, InstructorSourceList) and of the room, outsider and reservation lists still size text in rem. AiSelfTest sizes icons in px.
    • Settings: lecture-comfort-switch.css loops its sparkle/dust decoration. Reduced motion stops it; whether it stays at all is @yoni254's call.
    • Gantt: DayCapacityCell keeps the class names day-capacity-cell and group/cell as hooks for its own sx hover selectors. They carry no Tailwind styling.
    • Room vs. classroom terminology: see the glossary (§4).
